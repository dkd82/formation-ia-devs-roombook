TP Jour 1 · RoomBook : de la découverte à la fonctionnalité livrée Participants

Vous rejoignez l'équipe de RoomBook, une application de réservation de salles de réunion (backend Node/Express + frontend JavaScript). Pendant ce TP, vous allez la faire évoluer ticket après ticket : explorer, ajouter une fonctionnalité, corriger un bug, renforcer les tests, refactorer, puis comparer vos deux outils.

Durée totale : ≈ 2 h 30 · Outils : GitHub Copilot (VS Code) et Claude Code (CLI)

Mise en route

Prérequis

  • Node.js 20+, Git, VS Code avec l'extension GitHub Copilot (Chat) connectée
  • Claude Code installé en ligne de commande (commande claude disponible dans le terminal)
  • Le dépôt Git de la formation fourni par le formateur (votre fork ou votre copie du dépôt)

Étapes

  1. Clonez votre dépôt (git clone <url>), ouvrez-le dans VS Code et restez sur la branche main, qui contient le point de départ du jour 1.
  2. Installez les dépendances : npm install puis npm --prefix backend install.
  3. Vérifiez que les tests passent : npm test (3 tests verts attendus).
  4. Lancez l'API (npm run back) et, dans un 2e terminal, le frontend (npm run front), puis ouvrez http://localhost:5173.
  5. Vérifiez l'état du dépôt : git status (aucune modification) et git log --oneline.
  6. Pour chaque ticket, travaillez sur une branche : git switch -c ticket-1, git switch -c ticket-2…
L'anatomie d'un bon prompt
Contexte
Où en est-on ? Techno, fichiers, situation.
Tâche
Quel objectif précis et unique ?
Contraintes
Style, limites, ce qu'il ne faut pas toucher.
Critères de succès
Comment saura-t-on que c'est réussi ?

Règles de travail

  • Écrivez votre prompt vous-même dans les 4 blocs avant de lancer l'outil : contexte, tâche, contraintes, critères de succès.
  • Relisez chaque diff (git diff) avant d'accepter. Vous restez responsable du code.
  • Si l'outil tourne en rond après 3 essais : nouvelle session, meilleur contexte.
  • Un ticket = une branche = un ou plusieurs commits lisibles.
Aide-mémoire des outils

GitHub Copilot (VS Code)

  • Modes de Chat : Ask (questions), Edit (modifications ciblées), Agent (tâches multi-fichiers avec exécution)
  • Contexte : #file:chemin, #codebase, #selection
  • Commandes : /explain, /fix, /tests
  • Personnalisation : .github/copilot-instructions.md, .github/prompts/*.prompt.md, .github/agents/*.agent.md

Claude Code (CLI)

  • Démarrer : claude à la racine du projet ; citer un fichier : @chemin
  • Mode plan : Shift+Tab ; contexte : /clear, /compact, /cost, /context
  • Configuration : /init, /memory, /agents, /hooks, /help
  • Personnalisation : CLAUDE.md, .claude/commands/, .claude/agents/, .claude/settings.json

Les interfaces évoluent vite : en cas de doute, vérifiez dans la documentation de la version installée.

Le ticket

Vous découvrez RoomBook. Avant de toucher au code, l'équipe attend de vous une compréhension solide du projet : comment il est organisé et ce qui se passe quand un utilisateur réserve une salle.

Critères d'acceptation

Prompt d'exploration

Complétez chacun des quatre blocs dans la zone ci-dessous, puis copiez le prompt et collez-le dans le chat de votre outil.

ContexteOù en est-on ? Techno, fichiers, situation.
Qu'est-ce que le projet ? Quelles technos ? Qu'est-ce que vous savez / ne savez pas ?
TâcheQuel objectif précis et unique ?
Quelle question précise ? Un résumé ET un parcours de bout en bout.
ContraintesStyle, limites, ce qu'il ne faut pas toucher.
Lecture seule ? Comment éviter qu'il invente ? Quel niveau de précision ?
Critères de succèsComment saura-t-on que c'est réussi ?

Conseils par outil

J1-3

Bug : impossible de réserver juste après une autre réservation

Durée : 25 minOutil : Copilot ou Claude CodeNiveau : Moyen

Le ticket

Rapport d'Alice : « La salle Mont Blanc est occupée de 09:00 à 09:15 par la daily. Quand Bob essaie de réserver Mont Blanc de 09:15 à 10:00, l'application répond « Créneau déjà réservé ». Pourtant la salle est libre à 09:15 ! » Corrigez la cause du problème.

Critères d'acceptation

Prompt de débogage

Complétez chacun des quatre blocs dans la zone ci-dessous, puis copiez le prompt et collez-le dans le chat de votre outil.

ContexteOù en est-on ? Techno, fichiers, situation.
Comportement observé, comportement attendu, fichier concerné, données de l'exemple.
TâcheQuel objectif précis et unique ?
Reproduire d'abord (test rouge) ? Demander des hypothèses classées avant de corriger ?
ContraintesStyle, limites, ce qu'il ne faut pas toucher.
Périmètre de la correction ? Quels contournements interdisez-vous ? L'API doit-elle changer ?
Critères de succèsComment saura-t-on que c'est réussi ?
Quels tests doivent être rouges puis verts ? Quels comportements doivent rester identiques ?

Conseils par outil

GitHub Copilot (VS Code)

  • Sélectionnez la boucle de détection dans l'éditeur, puis utilisez Chat avec #selection pour cibler le contexte.

Claude Code (CLI)

  • Faites écrire le test, lancez npm test vous-même pour constater le rouge, puis demandez la correction.
  • Si la session s'embrouille : /clear puis relancez avec un contexte plus précis.

Vérifier avant de passer au ticket suivant

  • Constatez le test rouge avant correction (capture ou sortie du terminal).
  • npm test : tout vert après correction.
  • Essayez dans l'UI : 09:15–10:00 passe, 09:05–09:30 est refusé.
